# Honeypot Orchestrator

### AI-Powered Security Monitoring and Honeypot Platform

Honeypot Orchestrator is a cybersecurity monitoring platform built to study
malicious activity through intentionally vulnerable/deceptive services.

The system collects events generated by honeypots and attack simulations,
stores them in a central database, classifies the observed activity using a
machine learning model, and presents the results through a web dashboard.

The main goal of the project is to turn raw honeypot activity into information
that can be easily understood by a security analyst.

---

## What the Project Does

The platform provides three main components:

- Honeypot services that act as decoy targets
- A backend that receives and processes security events
- A dashboard for monitoring and analysing the collected activity

Attack events can be generated through the included simulator or captured from
the configured honeypot services.

Each event is processed by the backend and passed through the threat analysis
pipeline. The resulting information is then displayed on the dashboard.

---

## Main Features

### Honeypot Monitoring

The project includes decoy services designed to attract suspicious activity.

Currently supported environments include:

- HTTP
- Database
- SSH

These services generate events when an interaction takes place.

### Attack Classification

A Random Forest classifier is used to classify incoming events into different
attack categories.

The current model supports:

- Brute Force
- Command Injection
- Credential Attack
- SQL Injection
- Scanning
- Suspicious HTTP Activity
- XSS

The trained model is stored in:

`ml/models/attack_classifier.joblib`

### Attack Chain Visualization

The dashboard groups related activity into an attack progression:

`RECON → DISCOVERY → CREDENTIAL ATTACK → ACCESS ATTEMPT → COMMAND EXECUTION`

This provides a clearer view of how an attack can progress instead of showing
individual events in isolation.

### Threat Analysis

The backend combines machine-learning classification with rule-based analysis
to produce additional information about suspicious events.

This allows the system to continue providing useful results even when an event
does not clearly match the trained model.

### Security Dashboard

The frontend provides a central view of:

- Recent attack events
- Attack categories
- Severity information
- Attack progression
- Event details
- Threat information

The dashboard periodically requests new data from the backend so that newly
generated events appear without manually refreshing the page.

## Machine Learning

The project uses a Random Forest Classifier trained on features extracted from
security events.

### Model Details

| Property | Value |
|---|---|
| Algorithm | Random Forest |
| Number of Features | 10 |
| Number of Attack Classes | 7 |
| Reported Test Accuracy | 94.18% |

The features used by the classifier include:

- `payload_length`
- `failed_attempts`
- `has_xss_pattern`
- `has_sqli_pattern`
- `request_count`
- `is_http`
- `has_login`
- `is_ssh`
- `has_cmd_pattern`
- `is_db`

The trained model can be found in the `ml/models` directory.
